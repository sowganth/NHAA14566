# Stress Vulnerability Assessment Engine (SVI Engine)
### Module 2 — AI-enabled Real-Time Stress and Trauma Assessment System
**National Helpline Against Atrocities (NHAA 14566)**

---

## 1. Overview & Ethical Notice

The **Stress Vulnerability Assessment Engine (SVI Engine)** is a production-quality, explainable, and deterministic backend decision-support service. It receives structured psychological indicators and incident context generated by **Module 1 (AI Interaction & Emotion Analysis)**, evaluates individual indicator severities, computes an overall **Stress Vulnerability Index (SVI: 0–100)**, identifies critical safety flags, and provides non-clinical support priorities for **Module 3 (Dashboard & Support System)**.

> [!IMPORTANT]
> **CRITICAL ETHICAL & LEGAL NOTICE**:
> This service is strictly a **decision-support tool** for authorized human caseworkers. It is **NOT a clinical diagnostic system**.
> - It does **NOT** diagnose depression, PTSD, suicidal behavior, or any medical condition.
> - It does **NOT** determine guilt, innocence, or whether a complaint is genuine.
> - It does **NOT** infer caste identity from speech.
> - It does **NOT** make independent police, emergency, or legal intervention decisions.
> Every assessment payload includes `human_review_required: true/false` and a mandatory ethical disclaimer.

## 3. Installation & Setup

### Prerequisites
- Python 3.10+ (tested on Python 3.13)
- Git
- Docker & Docker Compose (optional for containerized deployment)

### Local Setup
1. Clone the repository and navigate into the service directory:
   ```bash
   cd svi-engine
   ```

2. Create and activate a virtual environment:
   ```bash
   # Windows
   py -m venv venv
   .\venv\Scripts\activate

   # Linux/macOS
   python3 -m venv venv
   source venv/bin/activate
   ```

3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

4. Configure environment variables:
   ```bash
   cp .env.example .env
   ```

```yaml
  sadness: 0.04
  helplessness: 0.07
  fear: 0.10

  ongoing_threat: 0.05
  speech_distress: 0.05

# Risk category thresholds
risk_levels:
  low: { min: 0, max: 25, label: "LOW" }
  moderate: { min: 26, max: 50, label: "MODERATE" }
  high: { min: 51, max: 75, label: "HIGH" }
  critical: { min: 76, max: 100, label: "CRITICAL" }

safety_rules:
  immediate_danger:
    enabled: true

    override_category: "CRITICAL"
    human_review_required: true
    priority: "URGENT_HUMAN_REVIEW"
  suicidal_ideation:
    enabled: true

    override_category: "CRITICAL"
    human_review_required: true
    priority: "URGENT_HUMAN_REVIEW"
  self_harm_indicator:
    enabled: true
    threshold: 40.0
    override_category: "CRITICAL"
    human_review_required: true
    priority: "URGENT_HUMAN_REVIEW"
```

## 5. Running the Service

### A. Run Locally (Development)
```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
By default, the engine connects to a local SQLite database (`svi_assessment.db`) if no PostgreSQL instance is configured.

### B. Run with Docker Compose (Production PostgreSQL)
```bash
docker-compose up -d --build
```
This boots up:
- FastAPI backend on `http://localhost:8000`
- PostgreSQL 16 on `localhost:5432` with automated health checks

### C. Run the Interactive Demo
To run the automated test suite across all 5 benchmark scenarios:
```bash
python demo.py
```

## 8. Missing Data Handling & Confidence Engine

1. **No Silent Zeroes**: Missing features (`null`) are tracked in `data_quality.missing_features`.
2. **Dynamic Re-normalization**: Available weights are re-normalized proportionally ($W_{\text{norm}} = W_i / \sum W_{\text{present}}$) so that missing values do not artificially deflate the SVI score.
3. **Confidence Penalty**:
   $$\text{Confidence} = 0.60 \times \text{Completeness} + 0.30 \times \text{Core Indicators Present} + 0.10 \times \text{Consistency}$$
   Confidence drops appropriately if critical indicators are missing.

## 9. Integration Guide for Team 1 (AI Interaction & Emotion Analysis)

1. Normalize all continuous emotion and speech metrics to integers/floats between **0 and 100**.
2. Pass binary flags (`immediate_danger`, `suicidal_ideation`, `self_harm_indicator`) directly in `features`.
3. If an indicator cannot be extracted from the audio/transcript, pass `null` or omit the key.
4. Pass atrocity context booleans in `context`.
5. Submit to:
   `POST http://<svi-engine-host>:8000/api/v1/assessment`
   Headers: `Content-Type: application/json`, `X-API-Key: demo-team1-key-14566` (if auth enabled).

---

## 10. Integration Guide for Team 3 (Dashboard & Support System)

1. Consume `assessment.risk_category` ("LOW", "MODERATE", "HIGH", "CRITICAL") for color-coded badge display.
2. Read `assessment.human_review_required` (boolean):
   - If `true`, display prominent **URGENT HUMAN REVIEW REQUIRED** banner.
3. Display `contributing_factors` as bullet points explaining why the score was given.
4. Display `feature_contributions` in a bar chart / radar chart showing exact weights and contributions.
5. Render `suggested_support` as actionable checklist items for caseworkers.
6. Display `disclaimer` on all screens.
7. Query past assessments using `GET /api/v1/assessment/{case_id}`.

## 11. Automated Test Suite

Run all unit and integration tests with pytest:
```bash
pytest tests/ -v
```

Covered test suites:
- **Test 1**: Low risk scenario (scores ~10–20 $\rightarrow$ LOW)
- **Test 2**: Moderate risk scenario (scores ~30–45 $\rightarrow$ MODERATE)
- **Test 3**: High risk scenario (scores ~55–70 $\rightarrow$ HIGH)
- **Test 4**: Critical risk scenario (scores ~80–95 $\rightarrow$ CRITICAL)
- **Test 5**: Immediate danger safety override ($\rightarrow$ CRITICAL + human review)
- **Test 6**: Missing data handling (re-weighting + confidence reduction)
- **Test 7**: Input validation (rejects `<0`, `>100`, string values, extra fields)
- **Test 8**: Explicit suicidal ideation safety trigger (and prevents false positives from sadness)
- **Test 9**: Batch assessment endpoint
- **Test 10**: Health check & database persistence
